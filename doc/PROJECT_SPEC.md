## 1. ภาพรวมและเป้าหมาย

### 1.1 ปัญหาที่ต้องการแก้
- ร้านเครื่องสำอางมีสินค้าจำนวนมาก หลายหมวด หลายล็อต และ **มีวันหมดอายุ** ทำให้ตรวจนับด้วยกระดาษ/Excel ผิดพลาดง่าย
- ไม่รู้ล่วงหน้าว่าสินค้าใดใกล้หมดหรือใกล้หมดอายุ → ขาดสต็อกหรือสินค้าเสียหาย
- ไม่มีประวัติว่าใครรับเข้า/จ่ายออก/ปรับยอดเมื่อไร ตรวจสอบย้อนหลังไม่ได้
- พนักงานหลายคนใช้งาน แต่ต้องการจำกัดสิทธิ์ตามหน้าที่

### 1.2 เป้าหมาย
1. ระบบคลังสินค้าที่ใช้งานได้จริง มีฐานข้อมูลถาวร มีระบบสมาชิก
2. บันทึกทุกการเคลื่อนไหวของสต็อก (รับเข้า / จ่ายออก / ปรับยอด) พร้อมผู้ทำรายการและเวลา
3. แจ้งเตือนสินค้าใกล้หมดและใกล้หมดอายุอัตโนมัติ
4. รองรับหลายร้านในระบบเดียว โดยข้อมูลแต่ละร้านแยกจากกันเด็ดขาด
5. ใช้งานลื่นไหลทุกขนาดจอ ไม่มีหน้าล้นหรือปุ่มกดไม่ได้บนมือถือ

### 1.3 ตัวชี้วัดความสำเร็จ
- ทำรายการรับเข้า/จ่ายออก 1 รายการบนมือถือได้ภายใน < 30 วินาที
- ยอดคงเหลือในระบบตรงกับผลรวมประวัติการเคลื่อนไหว 100%
- ผ่าน checklist Responsive ทุกอุปกรณ์ในหัวข้อ 16

## 3. ผู้ใช้ บทบาท และสิทธิ์

### 3.1 บทบาท (Roles)
| บทบาท | รหัส | หน้าที่โดยทั่วไป |
| --- | --- | --- |
| เจ้าของร้าน | `OWNER` | ผู้สร้างร้าน มีสิทธิ์ทุกอย่าง |
| ผู้จัดการ | `MANAGER` | ดูแลสินค้าและสต็อก ดูรายงาน |

| สิทธิ์ | OWNER | MANAGER | STAFF | VIEWER |
| --- | :-: | :-: | :-: | :-: |
| ดู Dashboard / สินค้า | ✓ | ✓ | ✓ | ✓ |
| เพิ่ม / แก้ไขสินค้า | ✓ | ✓ | — | — |
| ลบสินค้า | ✓ | — | — | — |
| รับเข้า / จ่ายออก | ✓ | ✓ | ✓ | — |

| ดูรายงาน / ส่งออก | ✓ | ✓ | — | ✓ |
| จัดการผู้ใช้และสิทธิ์ | ✓ | — | — | — |
| ตั้งค่าร้าน | ✓ | — | — | — |

### 3.3 กฎการบังคับใช้สิทธิ์
- ตรวจสิทธิ์ **ทั้งฝั่ง Server (บังคับ)** และฝั่ง UI (ซ่อน/ปิดปุ่มที่ไม่มีสิทธิ์)
- ร้านต้องมี OWNER อย่างน้อย 1 คนเสมอ — ห้ามลบ/ลดสิทธิ์ OWNER คนสุดท้าย
- ผู้ใช้ห้ามแก้ไขบทบาทของตนเอง
- สถานะผู้ใช้: `ACTIVE` (ใช้งานอยู่), `INVITED` (รอยืนยัน/รอตั้งรหัส), `DISABLED` (ระงับ)

## 4. การแยกข้อมูลแต่ละร้าน (Multi-tenant)

- โมเดล: **ฐานข้อมูลเดียว แยกด้วยคอลัมน์ `shopId`** (Shared DB, Shared Schema)
- ทุกตารางธุรกิจ (Product, Lot, Movement, Category, User) มี `shopId`
- `shopId` ได้มาจาก **session ของผู้ใช้เท่านั้น** ไม่รับจาก query/body ของ client
- ทุก query ต้องมีเงื่อนไข `WHERE shopId = session.shopId` — รวมไว้ใน helper กลาง เพื่อไม่ให้ลืม
- SKU และ Barcode **ไม่ซ้ำภายในร้านเดียวกัน** (unique `[shopId, sku]`) แต่ร้านต่างกันใช้ซ้ำได้
- เลขเอกสาร (RCV/ISS/ADJ) นับแยกต่อร้าน
- ทดสอบ: ผู้ใช้ร้าน A เรียก API ด้วย id ของร้าน B ต้องได้ 404

## 5. รายละเอียดแต่ละโมดูล

### 5.1 Login / สมัครร้าน / Logout (F01, F02, F16)
- **Login**: อีเมล, รหัสผ่าน (ปุ่มแสดง/ซ่อน), “จดจำฉัน”, ข้อความผิดพลาดภาษาไทย
- **สมัครร้าน**: ชื่อร้าน, ชื่อผู้ใช้, อีเมล, รหัสผ่าน (≥ 8 ตัว) → สร้าง Shop + User(OWNER) + หมวดเริ่มต้น
- **Logout**: อยู่ในเมนู “เพิ่มเติม” (มือถือ) / เมนูผู้ใช้ (เดสก์ท็อป) → ล้าง cookie แล้วกลับหน้า Login
- หน้าที่ต้องล็อกอินทั้งหมดถูก redirect ไป `/login` ถ้าไม่มี session
- ป้องกัน brute-force: จำกัดจำนวนครั้งที่ล็อกอินผิด

### 5.2 Dashboard (F05) — ตามภาพหน้าจอ
**การ์ดสรุป (KPI)**
| การ์ด | ความหมาย |
| --- | --- |
| สินค้า/SKU | จำนวนสินค้าที่ใช้งานอยู่ |
| คงเหลือรวม | ผลรวมจำนวนชิ้นทุกสินค้า |
| มูลค่าคลัง | Σ (คงเหลือ × ราคาทุน) แสดง ฿ |
| ใกล้หมด | 0 < คงเหลือ ≤ จุดสั่งซื้อ |
| สินค้าหมด | คงเหลือ = 0 |
| ใกล้หมดอายุ | ล็อตคงเหลือ > 0 ที่หมดอายุภายใน N วัน |
| หมดอายุ | ล็อตคงเหลือ > 0 ที่เลยวันหมดอายุแล้ว |
| รับวันนี้ / จ่ายวันนี้ | จำนวนชิ้นรับเข้า/จ่ายออกวันนี้ |

**ส่วนอื่น**
- กราฟแท่ง “สินค้าเข้า-ออก” รายเดือน (ย้อนหลัง 4–6 เดือน) สีลาเวนเดอร์ = รับเข้า, ชมพู = จ่ายออก
- กราฟโดนัท “มูลค่าตามหมวดหมู่”
- กล่อง “แจ้งเตือนสำคัญ” แยก สินค้าหมด / สต็อกต่ำ / ใกล้หมดอายุ + ปุ่ม “ดูทั้งหมด”
- “รายการล่าสุด” 5 รายการ: ไอคอนประเภท, ชื่อสินค้า, วันเวลา · ผู้ทำ · เลขเอกสาร, จำนวน, ยอดก่อน → หลัง
- ไอคอนกระดิ่งที่ Header แสดงจำนวนแจ้งเตือนทั้งหมด

### 5.3 สินค้า (F06, F14)
**ฟิลด์สินค้า**
| ฟิลด์ | ชนิด | บังคับ | หมายเหตุ |
| --- | --- | :-: | --- |
| ชื่อสินค้า | text | ✓ | |
| SKU | text | ✓ | ไม่ซ้ำในร้าน เช่น `SK-VC30` |
| บาร์โค้ด | text | | ไม่ซ้ำในร้าน (ถ้ามี) |
| หมวดหมู่ | select | ✓ | สกินแคร์, เมคอัพ, บำรุงผิว, คลีนซิ่ง, กันแดด (แก้ไขได้) |
| แบรนด์ | text | | |
| หน่วย | text | ✓ | ชิ้น / ขวด / หลอด / ตลับ (ค่าเริ่มต้น “ชิ้น”) |
| ราคาทุน | number ≥ 0 | ✓ | ใช้คำนวณมูลค่าคลัง |
| ราคาขาย | number ≥ 0 | | |
| จุดสั่งซื้อ (Reorder point) | int ≥ 0 | ✓ | ต่ำกว่าหรือเท่ากับนี้ = ใกล้หมด |
| รายละเอียด | textarea | | |
| สถานะ | active/archived | | |

- **รายการสินค้า**: มือถือแสดงเป็นการ์ด (อักษรย่อ/รูป, ชื่อ, SKU, หมวด, คงเหลือ, แท็กสถานะ); แท็บเล็ตแนวนอน = รายการ + แผงรายละเอียด + ประวัติ (Mockup 1f); เดสก์ท็อป = ตาราง (Mockup 2d)
- **แท็กสถานะ**: ปกติ / ใกล้หมด / หมด / ใกล้หมดอายุ
- **ค้นหา**: ช่องค้นหาด้านบน (ชื่อ, SKU, บาร์โค้ด), ตัวกรองหมวดหมู่และสถานะ, ปุ่มสแกน
- **เพิ่ม/แก้ไข**: ฟอร์มเดียว (Mockup 2b), ตรวจสอบค่าและแสดง error ใต้ช่อง
- **ลบ**: กล่องยืนยันการลบ (Mockup 2d) — ถ้าสินค้ามีประวัติการเคลื่อนไหว ให้ **เก็บถาวร (archive)** แทนการลบจริง เพื่อรักษาประวัติ; ลบจริงได้เฉพาะสินค้าที่ยังไม่มีรายการ

### 5.4 รับเข้า / จ่ายออก / ปรับยอด (F07, F08, F09) — ฟอร์มเดียว (Mockup 1d)
ฟอร์มมีแท็บ (segmented) 3 แบบ: **รับเข้า | จ่ายออก | ปรับยอด**

| ฟิลด์ | รับเข้า | จ่ายออก | ปรับยอด |
| --- | :-: | :-: | :-: |
| สินค้า (ค้นหา/สแกน) | ✓ | ✓ | ✓ |
| จำนวน | ✓ (> 0) | ✓ (> 0, ≤ คงเหลือ) | ✓ เพิ่ม/ลด |
| เลขล็อต | ✓ | เลือกได้ (ค่าเริ่มต้น FEFO) | เลือกล็อต |
| วันหมดอายุ | ✓ | — | — |
| ราคาทุนต่อหน่วย | ไม่บังคับ | — | — |
| เหตุผล | — | ขาย, เบิกใช้, ตัวอย่าง, อื่นๆ | ตรวจนับ, ชำรุด, หมดอายุ, อื่นๆ |
| หมายเหตุ / อ้างอิง | ✓ | ✓ | ✓ |

- แสดง **ยอดปัจจุบัน → ยอดหลังทำรายการ** แบบ real-time ก่อนกดยืนยัน
- เมื่อบันทึก: สร้างเลขเอกสารอัตโนมัติ `RCV-0001`, `ISS-0001`, `ADJ-0001`
- บันทึกใน **Transaction เดียว** (อัปเดตล็อต + สร้าง Movement) ป้องกันยอดเพี้ยน

### 5.5 ประวัติการเคลื่อนไหว (F10) — Mockup 2c

- ประวัติ **แก้ไข/ลบไม่ได้** — ถ้าผิดให้ทำรายการปรับยอดชดเชย

### 5.6 แจ้งเตือน (F11, F12) — Mockup 2a
- 2 แท็บ: **สต็อกใกล้หมด** | **ใกล้หมดอายุ**
- สต็อก: การ์ดแสดงชนิด (หมดสต็อก/สต็อกต่ำ), ชื่อ, SKU, “คงเหลือ X / จุดสั่งซื้อ Y”, แถบความคืบหน้า, ปุ่ม “รับเข้า” ลัด
- หมดอายุ: ชื่อ, เลขล็อต · จำนวน, วันหมดอายุ, “อีก N วัน” (หรือ “หมดอายุแล้ว”), ปุ่มปรับยอดตัดทิ้ง

### 5.7 รายงาน (F13) — Mockup 2f
- **สรุปตามหมวดหมู่**: หมวด, จำนวน SKU, รับเข้า, จ่ายออก, มูลค่าคงเหลือ

- **สินค้าเคลื่อนไหวสูงสุด** (Top จ่ายออก)
- เลือกช่วงวันที่ได้
- **ส่งออก CSV** (UTF-8 BOM เพื่อให้ Excel แสดงภาษาไทยถูก) และพิมพ์หน้า (print stylesheet)

### 5.8 ผู้ใช้และสิทธิ์ (F03) — Mockup 2e
- ตารางผู้ใช้: อักษรย่อ, ชื่อ, อีเมล, บทบาท, สถานะ, ใช้งานล่าสุด
- เพิ่มผู้ใช้: ชื่อ, อีเมล, บทบาท, รหัสผ่านชั่วคราว

- แสดงตารางสิทธิ์ (หัวข้อ 3.2) ให้เห็นผลของแต่ละบทบาท

### 5.9 Barcode / QR (F15)
- **สแกน**: ใช้กล้องผ่านเบราว์เซอร์ (`BarcodeDetector` API ถ้ามี, ไม่งั้น fallback เป็นไลบรารี เช่น `html5-qrcode`/`@zxing`) — ต้องเป็น HTTPS
- ใช้ได้ที่: ช่องค้นหาสินค้า, ฟอร์มรับเข้า/จ่ายออก/ปรับยอด, ฟอร์มสินค้า (กรอกบาร์โค้ด)

- **สร้าง QR** ของสินค้า (เข้ารหัส SKU) แสดงในหน้ารายละเอียด และพิมพ์ได้
- ถ้าไม่มีกล้อง/ไม่อนุญาต ให้พิมพ์รหัสเองได้เสมอ

## 6. โครงสร้างข้อมูล (Data Model)

```text
Shop 1 ── * User
Shop 1 ── * Category 1 ── * Product
Shop 1 ── * Product 1 ── * Lot
Product 1 ── * Movement * ── 1 User (ผู้ทำรายการ)
Movement * ── 0..1 Lot
```

| ตาราง | ฟิลด์หลัก |
| --- | --- |
| **Shop** | id, name, expiryAlertDays (default 60), createdAt |
| **User** | id, shopId, name, email (unique), passwordHash, role, status, lastActiveAt, createdAt |
| **Category** | id, shopId, name, color — unique(shopId, name) |
| **Product** | id, shopId, categoryId, sku, barcode?, name, brand?, unit, costPrice, salePrice?, reorderPoint, description?, archived, createdAt, updatedAt — unique(shopId, sku), unique(shopId, barcode) |
| **Lot** | id, shopId, productId, lotNo, expiryDate?, qty (คงเหลือในล็อต), receivedAt |
| **Movement** | id, shopId, productId, lotId?, userId, type (`IN`/`OUT`/`ADJUST`), docNo, qty (มีเครื่องหมาย), balanceBefore, balanceAfter, reason?, note?, createdAt |
| **DocCounter** | shopId, type, seq — ใช้ออกเลขเอกสาร |
| **Session** (ถ้าใช้) | id, userId, expiresAt |

- **คงเหลือสินค้า** = Σ `Lot.qty` ของสินค้านั้น
- ราคาเก็บเป็น Decimal(12,2), วันที่เก็บ UTC แสดงผลเป็นเวลาไทย (Asia/Bangkok) และปี พ.ศ.

## 7. กฎทางธุรกิจ (Business Rules)

| รหัส | กฎ |
| --- | --- |
| BR1 | สต็อกห้ามติดลบ — จ่ายออก/ปรับลดเกินคงเหลือไม่ได้ |
| BR2 | จ่ายออกตัดล็อตแบบ **FEFO** (หมดอายุก่อน ออกก่อน); ล็อตไม่มีวันหมดอายุตัดท้ายสุด |
| BR3 | สถานะสินค้า: `หมด` ถ้าคงเหลือ = 0; `ใกล้หมด` ถ้า 0 < คงเหลือ ≤ จุดสั่งซื้อ; `ใกล้หมดอายุ` ถ้ามีล็อตคงเหลือหมดอายุภายใน N วัน; นอกนั้น `ปกติ` |
| BR4 | ล็อตหมดอายุแล้ว (expiryDate < วันนี้) ที่ยังมีคงเหลือ → แจ้งเตือน “หมดอายุ” |
| BR5 | ทุกการเปลี่ยนยอดต้องเกิดผ่าน Movement เท่านั้น — ไม่มีการแก้ยอดตรง |
| BR6 | Movement แก้ไข/ลบไม่ได้ (audit trail) |
| BR7 | สินค้าที่มี Movement ลบจริงไม่ได้ → archive |
| BR8 | เลขเอกสารรันต่อเนื่องต่อร้านต่อประเภท ไม่ซ้ำ |
| BR9 | การทำรายการสต็อกเป็น DB transaction เดียว ป้องกันการแข่งกันอัปเดต |
| BR10 | มูลค่าคลัง = Σ (คงเหลือ × ราคาทุนปัจจุบัน) |

## 13. ความปลอดภัย

- รหัสผ่าน hash ด้วย **bcrypt** (cost ≥ 10) ไม่เก็บ plain text
- Session cookie: `httpOnly`, `secure`, `sameSite=lax`, หมดอายุ (เช่น 7 วัน / 30 วันถ้า “จดจำฉัน”)
- ตรวจสิทธิ์ + `shopId` ฝั่ง server ทุก request (ป้องกัน IDOR)
- Validate input ด้วย Zod, Prisma ป้องกัน SQL injection
- จำกัดความถี่การล็อกอินผิด
- ความลับ (`DATABASE_URL`, `SESSION_SECRET`) อยู่ใน Environment Variables ของแพลตฟอร์ม ไม่ commit ลง git
- HTTPS บังคับ (Vercel/Render ให้อัตโนมัติ) — จำเป็นต่อการใช้กล้องสแกนด้วย

## 14. การ Deploy

### 14.1 Environment Variables
| ชื่อ | ตัวอย่าง | หมายเหตุ |
| --- | --- | --- |
| `DATABASE_URL` | `postgresql://user:pass@host/db?sslmode=require` | Connection string (pooled) |
| `DIRECT_URL` | `postgresql://…` | สำหรับ migration (ถ้าใช้ Neon) |
| `SESSION_SECRET` | สุ่ม ≥ 32 ตัวอักษร | เซ็น session |

### 14.2 ตัวเลือก A — Vercel + Neon Postgres (แนะนำ)
1. Push โค้ดขึ้น GitHub
2. Vercel → New Project → Import repo (Framework: Next.js)
3. Storage → เพิ่ม Neon Postgres (หรือสร้างที่ neon.tech แล้วใส่ `DATABASE_URL`)
4. ตั้ง `SESSION_SECRET`
5. Build command: `prisma generate && prisma migrate deploy && next build`
6. รัน seed ครั้งแรก: `npx prisma db seed` (จากเครื่องโดยชี้ `DATABASE_URL` ไป production)

### 14.3 ตัวเลือก B — Render
1. สร้าง **PostgreSQL** บน Render → คัดลอก Internal Database URL
2. สร้าง **Web Service** จาก GitHub repo
   - Build: `npm ci && npx prisma generate && npx prisma migrate deploy && npm run build`
   - Start: `npm start`
3. ใส่ Environment Variables
4. (มี `render.yaml` แบบ Blueprint เพื่อสร้างทั้งสองอย่างอัตโนมัติ)
5. หมายเหตุ: แพ็กเกจฟรีของ Render จะ sleep เมื่อไม่มีการใช้งาน และฐานข้อมูลฟรีมีอายุจำกัด

### 14.4 Checklist ก่อนส่งงาน
- [ ] เปิด URL production ได้ผ่าน HTTPS
- [ ] สมัครร้านใหม่ / ล็อกอิน / ล็อกเอาต์ได้
- [ ] บัญชีตัวอย่างใช้งานได้ (ดูหัวข้อ 15)
- [ ] ทดสอบบนมือถือจริงอย่างน้อย 1 เครื่อง (iPhone/Android)
